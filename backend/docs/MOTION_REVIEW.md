# Interaction and AI activation update — 2026-09-05

This focused frontend review found flat press states, abrupt dialog/task changes, and no touch navigation between encounter tasks. The update adds 65 ms press feedback, 120–180 ms settling transitions, a one-pixel desktop hover lift, active navigation feedback, restrained dialog/backdrop entry and brief notice feedback. Motion changes transform/opacity rather than element dimensions. No decorative looping animation or animation delay is added to an action.

Horizontal touch gestures move between Findings, Evidence, Case review and Document. Feedback follows the finger with bounded displacement and resistance at the first/last task. A deliberate minimum distance and horizontal direction are required; short taps, vertical scrolling, mouse selection, additional fingers and cancelled gestures do not change the task. Gestures beginning on editable controls or action buttons are ignored. Switching tasks does not submit, confirm, reject, sign or edit evidence/document data. There is no swipe-to-delete or automatic clinical action.

Settings → Motion offers Follow device (default), Subtle motion, and Reduce motion. Device accessibility preferences suppress movement by default. Subtle motion is an explicit application preference, useful when an embedded browser reports reduced motion. Reduce motion suppresses transitions and animations while keeping touch navigation available. The preference persists on that browser/device.

Verification: all 35 frontend tests passed, including five new gesture regressions and the existing exact-text, signing, recovery and accessibility tests. ESLint and the strict TypeScript/Vite production build passed. Actual browser inspection verified the device's reduced-motion request was honored, then the explicit Subtle motion preference enabled 120–180 ms transitions and the 180 ms dialog animation. No horizontal document overflow or vertical tab overflow was observed in the inspected desktop view. Hardware touch/OS gesture behavior is not a completed device acceptance benchmark.

Provider execution and optional medical transcription are activated separately through protected server configuration at the owner's request. No live inference or transcription request is used to verify this update, and no provider credits are purchased. Public capability flags and deployed frontend assets are checked without calling providers. OpenRouter funding remains the owner's next step; clinical-data approvals and payment activation remain separate.
