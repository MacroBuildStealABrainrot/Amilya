# Restricted Render test-account enrollment

The separate Render database did not contain an application account. Existing
Cloud Run credentials are not copied or forwarded. Test14 already supports the
normal account-creation screen, but the server had closed signup entirely.

This correction permits one username to register in the empty isolated test
account database, for at most 24 hours. Configure the non-secret variables
`RENDER_OWNER_ENROLLMENT_EMAIL` and `RENDER_OWNER_ENROLLMENT_UNTIL` (Unix seconds)
on the existing Render test service after CI passes. These Dashboard-owned
variables are omitted from the Blueprint and preserved by later syncs.

`ALLOW_SIGNUP` stays false. Enrollment additionally requires the exact Render
test origin, dedicated database, production/secure-cookie context, and all
clinical-data, AI, billing, test-provider and schema-creation switches disabled.
The owner uses the app's existing Create account form, chooses a password there,
and explicitly accepts the current policies. No password or legal acceptance
is generated by the assistant. Email is a restricted username; this does not
claim mailbox verification or import another account's identity or records.

The first user closes enrollment automatically. The unique email constraint
prevents concurrent claims from creating multiple users. No platform admin
privilege, paid plan, payment, AI entitlement or provider activation is
granted. Existing signup rate limits, policy-version checks, password hashing,
secure sessions and audit behavior remain in force. Other deployments default
to no enrollment configuration, and their existing signup behavior is unchanged.

This fixes the missing account-creation path. It does not certify phone login
until the owner registers and signs in, and it does not enable photo assessment.
